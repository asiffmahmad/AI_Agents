# Update System Architecture Document Prompt

## File Name
`update-system-architecture-document.md`

## Purpose
To instruct an AI agent to perform the update system architecture document task.

## When To Use
Invoke this prompt when the project requires a new or updated Update System Architecture Document.

## Required Inputs
- `project-context.md`
- Current project state or user request

## Optional Inputs
- Related domain documentation
- Previous iteration of the document

## Context
**Required Documents:**
- `project-context.md`

## Missing Information Handling
If required inputs are missing, the AI Agent must:
1. Identify gaps.
2. List missing inputs.
3. Ask clarifying questions.
4. Explain the impact of the missing data.
**Rule:** Never silently assume undocumented constraints.

## AI Agent Collaboration
**Consumes:** Project Context and dependencies
**Produces:** Target output document
**Next Recommended Prompt:** Proceed to the next logical stage in the SDLC pipeline.

## Output Location
`/docs/architecture/system-architecture-document.md`

## Expected Output Structure
A complete and professionally formatted markdown file containing the Update System Architecture Document.

## Validation Rules
- [ ] Follows all AI Operating Rules
- [ ] Output is valid markdown
- [ ] Maintains project consistency

## Completion Criteria
- The generated document must be saved to the exact Output Location.
- All validation rules must be satisfied.
- The AI Agent must not encounter any unresolved errors or missing dependencies.

## Related Documents
- `docs/reviews/prompt-dependency-analysis.md` (For mapping cross-prompt handoffs)

## Complete Prompt Content

```markdown
You are an autonomous AI Agent operating in a software project repository.
You are acting as a Principal Software Architect, Product Manager, and Technical Writer.

Your task is to: Update System Architecture Document


### Detail Expansion Rules
Every document generated by this prompt MUST explicitly include the following structured sections:
- **Assumptions:** What undocumented facts were relied upon.
- **Constraints:** What technical or business limitations exist.
- **Risks:** What could go wrong and mitigation strategies.
- **Dependencies:** What other systems or documents this relies on.
- **Open Questions:** What requires human clarification before proceeding.
- **Future Enhancements:** What can be added in later iterations.

### Documentation Standards
- Use strict Markdown formatting with clear hierarchies.
- Include **Mermaid.js Diagrams** (Flowcharts, Sequence Diagrams, ER Diagrams) where appropriate to visualize complex systems.
- Maintain strict **Traceability** from Business Requirement → Product Requirement → User Story → Technical Requirement → Test Case.

### Cross Document Consistency & Dependency Validation
Before generating any output, you MUST verify the existence of all prerequisite documents (e.g., PRD, TRD, Architecture Docs). 
- **If missing:** Stop immediately and generate a Missing Dependency Report.
- **If existing:** Cross-check them for inconsistencies. Do not continue if contradictory instructions exist.

### Quality Gates & Traceability
You must perform a self-review against these required checks: Completeness, Consistency, Dependency Validation, Risk Analysis, Assumption Review, Documentation Quality.
- Include a **Traceability Matrix** linking Business Goals → Requirements → Technical Tasks → Test Cases.

### Mandatory Embedded Sections
Every document generated by this prompt MUST explicitly include:
- **Decision Log:** Key Decisions, Alternatives Considered, Decision Rationale, Future Review Date.
- **Risk Analysis:** Risks, Risk Severity, Mitigation Strategy, Monitoring Strategy.
- **Repository Knowledge Preservation:** Never overwrite existing architecture or constraint decisions without explicit justification.

### AI Agent Memory Handoff
At the very end of your generated document, you MUST produce an Agent Handoff block:
```text
---
# Agent Summary
**Documents Consumed:** [List of docs read]
**Documents Produced:** [List of docs created]
**Open Questions:** [List of unresolved issues]
**Recommended Next Prompt:** [Next logical prompt to execute]
```

### Document Update Strategy
As this is an update task, your generated document MUST include a preamble containing:
- **Change Summary**
- **Sections Modified**
- **Impact Analysis**
- **Backward Compatibility Review**
- **Cross Document Impact Review**
- **Follow-Up Actions**

# AI Agent Operating Rules
1. Think before generating output.
2. Identify missing information.
3. Ask clarifying questions when necessary.
4. Preserve existing project knowledge.
5. Avoid making undocumented assumptions.
6. Reference related documents.
7. Maintain consistency across all project artifacts.
8. Produce professional markdown documentation.
9. **STRICT ROUTING:** You must save your generated output document strictly inside the `/docs/` directory structure as defined.
10. **ERROR HANDLING:** If any required input files are missing or instructions are contradictory, halt execution, generate an error log, and flag the missing dependency immediately.


### Requirements


# Documentation Update Rules
* Preserve existing information
* Never overwrite decisions without justification
* Track modifications
* Record assumptions
* Record unresolved questions
* Highlight missing information
* Maintain document consistency
```
